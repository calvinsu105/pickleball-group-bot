PICKLEBALL GROUP BOT · 架構

匹克球揪團小幫手，訊息怎麼跑

機器人由四個網路服務組成：LINE 負責收發訊息，Render 執行程式，Neon 保存揪團與投票，GitHub 存放程式碼並觸發部署。Render 是中心，其他服務都只和它溝通。

服務關係圖

兩種事件的完整流程

團主建立揪團

  1. LINE團主在群組傳「揪團」訊息，日期、時間、場地、價錢各一行
  2. LINE → RenderLINE 平台把訊息 POST 到 /callback，附上簽章
  3. app.py用 Channel secret 驗證簽章，確認真的是 LINE 送來的
  4. polls.py拆出各欄位，缺欄位就回覆提醒
  5. db.py → Neon在 polls 表新增一筆揪團
  6. cards.py → LINE產生報名卡片，用 reply API 回覆到群組

成員按「參加」

  1. LINE按鈕送出 postback，內容像 action=vote&poll=12&choice=yes
  2. LINE → Render同樣 POST 到 /callback
  3. app.py → LINE向 LINE 查詢這位成員在群組裡的名稱
  4. db.py → Neon寫入或更新 votes 表的投票
  5. polls.py讀出所有投票，依時間排出正取、候補、不參加
  6. cards.py → LINE回覆最新名單卡片

每個服務的角色與免費方案限制

LINE 平台收發群組訊息。機器人只用 reply 回覆，不會用到每月推播額度。
Render執行程式。閒置 15 分鐘會休眠，喚醒約 1 分鐘；每月 750 小時免費。
Neon保存揪團與投票。閒置 5 分鐘會暫停，下次使用時自動喚醒，資料不會遺失。
GitHub存放程式碼。改完檔案存檔，Render 會自動重新部署。

群組安靜一陣子後，第一個按按鈕的人要等最久：Render 喚醒約 1 分鐘，Neon 再喚醒一下。之後的操作都會即時回應。
